# AGENTS.md

GNUstep/Objective-C desktop components (Menu, pref panes, apps) for the Gershwin
desktop. Built with GNUstep Makefiles and ARC (`-fobjc-arc`,
`-fobjc-runtime=gnustep-2.0`). The whole stack ships in `/System`; installs go
to the SYSTEM domain unless noted.

## Build / install

- Depends on the full Gershwin/GNUstep stack in `/System`. The top-level
  `GNUmakefile` only dispatches to subdirs; it does not build the GNUstep libs.
- Build all (except library consumers): `gmake`
- Build one component: `cd <dir> && gmake`
- Install all: `sudo gmake install` — installs `Libraries` first, then builds
  the **library consumers** (`Menu Network Sound Whisper`) that `gmake` alone
  skips. So a changed component only compiles during `install` if it links a
  backend from `Libraries/`.
- Install one component: `cd <dir> && sudo gmake install
  GNUSTEP_INSTALLATION_DOMAIN=SYSTEM`
- Clean: `gmake clean`. Root-owned build artifacts (`obj/`, `.app`, `Build`)
  must be `sudo rm -rf` before a clean rebuild.
- Never install to LOCAL; after installing verify nothing of ours landed in
  `/Local`. Menu must go to SYSTEM (`Menu/GNUmakefile` hardcodes
  `INSTALL_APPS_DIR=/System/Library/CoreServices/Applications`).

## Repository layout

- Flat: each top-level dir is a component (app, pref pane, bundle, or tool).
- `Libraries/` holds shared backends (`SoundBackend`, `NetworkBackend`) that
  `Menu`, `Network`, `Sound`, `Whisper` link against.
- `make_appimage/` is a GNUstep tool (`make_appimage`, `make_standalone`) that
  packs built `.app`/`.bundle` dirs into self-contained AppImages; uses
  `appimagetool` + `patchelf`.
- `DriveUI/` and `UIBridge/` are separate UI-driving/test systems (drive_ui CLI
  + DO-free bundle, and a DO-based server). Do not conflate them.

## Target file pitfalls

- `Menu/GNUmakefile` is generated from `Menu/GNUmakefile.in` (only diff is
  `@DBUS_LIBS@` vs `-ldbus-1`). When changing Menu's build config, edit **both**
  `GNUmakefile.in` and the committed `GNUmakefile` so they stay in sync.
- Cross-platform blocks fall back on `UNAME_S` (Linux/FreeBSD/NextBSD/OpenBSD).
  Keep every platform's branch working; CI builds FreeBSD, Arch, Debian, OpenBSD.
- Menu icons: edit the `.svg` sources, not the `.png` — PNGs are regenerated by
  ImageMagick `convert ... -resize 18x18!` from the SVGs in the build. A rebuilt
  PNG is byte-different even when visually identical, so don't commit PNG churn
  unless intended.

## Testing

- Components occasionally include bare test tools: `make_gorm/Tests/` uses
  `TEST_TOOL_NAME` + `test-tool.make`; `ICNSImageRep/test/` has `test_icns.m`;
  `Menu/` has `test.sh` / `test-menu-integration.sh`; `Assistants/BackupAssistant/`
  has shell+ObjC test tools. Inspect the component's `GNUmakefile` for the exact tool.
- For GNUstep unit/red-green tests, follow the global `gnustep-red-green-tdd`
  skill (PASS macro set + wiring).
- To drive/inspect a running GUI, use the driveui skill / `drive_ui`.

## Conventions

- Commit to `dev` (never `main` directly). Commit message style is
  `Area: short summary` (e.g. `Menu: suppress BadWindow flood from racing
  window scans`). Commit only when asked.
- No em-dashes in text; use plain `-`.
- New files: if the project is non-GPL, header
  `Copyright (c) 2026 Simon Peter / SPDX-License-Identifier: BSD-2-Clause`.
- Always fix build warnings and rebuild clean before finishing.
